# Klenz website — project guide

Online shop + admin for **Klenz** tissue products (Pollachi, Tamil Nadu). Built from the design "Kenz Website Design.html"; the logo, packaging, catalogue and visiting card say **Klenz**. Products have a price per pack (0 = "Price on request"). Checkout happens in the **cart popup**: cart → details → payment (**pay now** with a UPI QR for the exact total, or **pay later**) → order saved, and the **server** sends it to the admin's WhatsApp automatically (CallMeBot alert to the orders number, setting `order_whatsapp`, default +91 95663 78152, once the CallMeBot key is saved in Admin → Settings; the dashboard warns while it is not). The customer's browser opens nothing; the number shown on the site stays `whatsapp_number`. Read this file instead of exploring the code; open only the files a change needs. Live: https://klenz-tissue.onrender.com. History, decisions and open client items: `CHANGELOG.md`.

## Stack and ports
- `frontend/` React 19 + TypeScript 6 + Vite 8, React Router 8 (declarative `<Routes>`), CSS Modules, no UI library (QR codes: `uqr`). Dev server :5173 proxies `/api` to :8000.
- `backend/` FastAPI + SQLAlchemy 2.1 (sync) + PyMySQL, Pydantic v2, PyJWT. Port :8000. In production it also serves `frontend/dist` (one port, SPA fallback).
- Database: MySQL via `DATABASE_URL` in `backend/.env`. This PC: WAMP **MySQL 5.0.27**, user `root`, no password, database `klenz`, **`?charset=utf8`** (5.0 has no utf8mb4; use utf8mb4 on MySQL 5.5+/8). Tests use SQLite unless `TEST_DATABASE_URL` is set.
- `Images/` the client's originals (logo, catalogue `products.jpeg`, product photos, visiting card). `tools/` scripts that turn them into web images and videos.
- Hosting (all free): GitHub **https://github.com/manojbalu08/Klenz** (public, branch `main`). `.github/workflows/deploy.yml` runs pytest (SQLite, then MySQL 8.4 with Aiven-like strictness: TLS only, primary keys required, ANSI sql_mode), lint + build and `docker build`. On `main` it then POSTs the Render deploy hook with `ref=<sha>` (secret `RENDER_DEPLOY_HOOK_URL`) and polls `SITE_URL/api/health` until `commit` matches. `.github/workflows/keep-alive.yml` opens `/api/ping` every 10 minutes so Render doesn't sleep and Aiven doesn't switch the free database off. A failed run emails the repo owner; troubleshooting is in DEPLOY.md, "Site does not open". **Render** free web service `klenz-tissue` (https://klenz-tissue.onrender.com; the onrender.com name is fixed at creation) from `render.yaml` (Docker, Singapore, auto-deploy off, sleeps after 15 min idle) serves the site + API. **Aiven** free MySQL: `DATABASE_URL` = its Service URI (`mysql://…?ssl-mode=REQUIRED`). Root `Dockerfile`: Node builds `frontend/dist`, then uvicorn on `$PORT`, proxy headers trusted, non-root. GitHub Pages is not an option (GitHub forbids shops and password logins there). Steps and checklist: `DEPLOY.md`.

## Backend map (`backend/app/`)
- `main.py` `create_app()`: lifespan `prepare_database()` creates the MySQL database if missing → `create_all` tables → `add_missing_columns` → `seed_database`. If the database is unreachable at start (OperationalError, e.g. Aiven switched it off), the app starts anyway and a `db-retry` thread retries every `DB_RETRY_SECONDS` (30); any OperationalError in a request becomes **503 "The shop is waking up"**. It mounts the routers. `/api/health` never touches the database (status, database, `ready`, deployed `commit`; Render's health check). `/api/ping` runs `SELECT 1` (keep-alive; 503 while the database is down). It also serves `frontend/dist`.
- `config.py` `AppConfig` (env vars / `.env`; `git_commit` from `GIT_COMMIT`/`RENDER_GIT_COMMIT`/`RAILWAY_GIT_COMMIT_SHA`). `database.py` `parse_db_url` (plain `mysql://` → PyMySQL, `ssl-mode=REQUIRED` → encrypted without cert check), engine, `add_missing_columns` (ALTER TABLE ADD for model columns an existing table lacks), `UTCDateTime` (naive UTC, whole seconds), MySQL charset/InnoDB handling, `get_db`.
- `models.py` tables `admin_users, products (name, category, spec = pack size, price, description, art, tint, image_url, is_live, sort_order), orders (total, payment_method now|later, payment_status pending|reported|paid, payment_ref = UTR), order_items (product_name + product_spec + unit_price snapshot, quantity, line_total), videos, page_content, site_settings`. Money = `Numeric(10,2)` (Decimal; JSON as numbers). Order reference = `KZ-` + (10000 + id). Order `status` new → quoted (shown as "Confirmed") → closed.
- `schemas.py` request/response models + validators (`is_link`: `https://…` or `/path`; UPI ID; UTR). `content_schema.py` **every editable site text**: `PAGES` → fields `page.key` with label, default, kind text/textarea/url; `PREVIOUS_DEFAULTS` = old default texts that `seed.upgrade_default_content` swaps for the new default on start (only if unedited).
- `store.py` `SETTING_DEFAULTS` (`whatsapp_number` shown on the site, `order_whatsapp` receives orders, phones, email, address, hours, country code, `upi_id`, `upi_name`) + read/write; admin-only alert settings (`alert_phone`, `alert_apikey`, never in `SiteSettingsOut`); alert phone = alert_phone → order_whatsapp → whatsapp_number. `seed.py` first-run data (10 catalogue products with starting prices in `PRODUCTS`, 3 videos, page text, settings, 3 sample enquiries; marker `_seeded_at`), `set_starting_prices` (once per database, marker `_prices_set_at`: products still at 0 get their starting price; afterwards the admin owns prices), `upgrade_default_content`, `ensure_admin`.
- `notify.py` `rupees()` (Indian grouping), `order_alert_text`, `send_whatsapp` (CallMeBot GET; only reaches the phone that activated it), `send_order_alert` (background task, failures only logged).
- `security.py` PBKDF2 passwords, JWT (`sub`, `ver`=token_version, `rem`), `get_current_admin`. `ratelimit.py` in-memory limits (login failures, orders/hour).
- `routers/public.py` `GET /api/site` (settings, content, live products, videos in one call), `POST /api/orders` (prices from the DB, total, payment method/ref → status `reported` for "now"; 409 if a product is unavailable; queues the WhatsApp alert). `routers/auth.py` login, me.
- `routers/admin/` (all need a Bearer token): `dashboard`, `products` (+`/reorder`), `orders` (filter/search, PATCH `status` and/or `payment_status`, delete), `content`, `videos` (+`/reorder`), `settings` (+`/settings/alerts` GET/PUT, `/settings/alerts/test`, `/account/password` bumps token_version).
- `cli.py` init-db, set-password, schema-sql. `tests/` pytest; `conftest.make_client(**config_overrides)`; monkeypatch `app.notify.send_whatsapp` to test alerts.

## Recipes
- **Change site text, products, prices, photos, videos, WhatsApp numbers, UPI ID**: no code; use the admin (Page content, Products, Settings).
- **New text on a page**: add a `ContentField` in `content_schema.py`, then render `c['page.key']` in the page component. No migration needed. **Changing a default text**: also add the old text to `PREVIOUS_DEFAULTS` so unedited copies (live site too) update on the next start.
- **New setting**: `SETTING_DEFAULTS` (store.py) + `SiteSettingsIn/Out` (schemas.py) + `SiteSettings` (types.ts) + a field in `SettingsPage.tsx`. Secrets go in admin-only keys like `ALERT_APIKEY`, never in `SiteSettingsOut`.
- **New column** (e.g. a product field): add it to the model **with a `server_default`**, then `ProductIn`/`ProductOut` + `types.ts` + `ProductForm`. `add_missing_columns` adds it to existing databases (local and live) on the next start; renames/type changes still need SQL by hand.
- **Product photo**: copy the file to `frontend/public/images/products/` and set the product's photo to `/images/products/<name>.jpg` (or any https link). From the catalogue: adjust the boxes in `tools/crop_catalogue.py` and rerun it (it puts the real logo on).
- **Video**: put `name.mp4` (+ optional poster `name.jpg`) in `frontend/public/videos/` and add `/videos/name.mp4` in Admin → Page content → videos. YouTube/Vimeo links work too. Regenerate the made videos with `tools/make_videos.py` (text, phone number and timings are at the top and in `JOBS`).
- **Colours**: edit the `:root` variables in `styles/global.css` (shop and login) and the `--a-*` variables at the top of `admin/AdminLayout.module.css` (admin).
- **New shop page**: `shop/XPage.tsx` + route in `App.tsx` + `NAV` in `Header.tsx` (+ `LINKS` in `Footer.tsx`). **New admin page**: `admin/XPage.tsx` + route in `AdminApp.tsx` + `NAV` in `AdminLayout.tsx`.
- **New endpoint**: router in `routers/` (admin ones in `routers/admin/` are protected automatically) + function in `lib/api.ts` + type in `types.ts` + a test.
- **Animate a new block**: wrap it in `<Reveal delay={ms}>` (fade-up on scroll). Keep motion behind `useReducedMotion()` / `prefers-reduced-motion`.
- **New section**: give it `ui.themed` and put `<ThemeBackdrop />` first inside (`tone="hero"` on a `ui.pageHero`, `tone="dark"` on navy; pick a `layout` different from the sections around it). No plain or static-circle backgrounds: every section has the animated one.

## Conventions and gotchas
- Styles follow the design's pixel values. Colours only through CSS vars: `--ink --primary --soft --soft2 --accent --bg --muted --card --on-ink-muted`; `--focus` sets the focus-ring colour.
- When a component module overrides a class from `ui.module.css`/`admin.module.css`, use a two-class selector; CSS order between modules is not guaranteed. Reveal uses the `translate` property so hover effects can use `transform`; elements with both list their transitions together (see `ProductCard.module.css`, `ContactPage.module.css`).
- Old TV browsers: no `:has()`; selected states use data attributes (e.g. `data-selected` on the payment options).
- `ui.themed` = `position: relative; isolation: isolate; overflow: hidden`, and the backdrop sits at `z-index: -1` inside it, so section content needs no z-index. `ShopLayout` is a flex column: the footer stays at the bottom of short pages and the last section of `main` stretches to meet it.
- Responsive: phones ≤760px (header scrolls away, floating cart button, footer leaves room for it), cart popup full screen ≤560px, admin sidebar becomes a top bar ≤960px, TVs/large screens scale with `zoom` 1.1 / 1.33 / 2 at ≥1880 / 2400 / 3200px (ShopLayout, AdminLayout, LoginPage CSS). Build target is old enough for Smart TV browsers (`vite.config.ts`).
- Videos must be muted to autoplay; `HeroArt` and `VideoShowcase` set `muted` on the element before `play()`.
- Money: prices are taken from the database at order time (never from the browser); totals in the browser are summed in paise. A total of 0 with unpriced items shows "On request" (`orderTotal`). "Pay now" needs a total above 0.
- UPI: the QR is a static `upi://` link (no payment gateway, no fees); a payment is only "reported" until the admin checks the bank and marks it Paid. Without a UPI ID the QR is a clearly marked sample that pays nothing.
- WhatsApp alerts: CallMeBot only messages the phone that activated it, and a key only works with that phone's number ("APIKey is invalid" = key and number don't match). Its activation number changes now and then: `CALLMEBOT_NUMBER` in `SettingsPage.tsx` + DEPLOY.md (+34 644 45 70 57 in Oct 2026). The API key is write-only in the admin and never returned by any endpoint.
- TypeScript: `erasableSyntaxOnly` (no enums or parameter properties), `verbatimModuleSyntax` (`import type`). React 19: `<Context value>` providers, `<title>` inside pages.
- MySQL compatibility: indexed VARCHAR ≤191 chars, no JSON columns or CHECK constraints, datetimes via `UTCDateTime`, new columns need a `server_default`. SQLAlchemy `URL.set(database=None)` means "unchanged", so use `database=""`. SQLite stores Decimal as float (warning filtered in `pytest.ini`).
- Starlette 1.x TestClient needs `httpx2` (in requirements-dev.txt).
- Starter data is added once. To start a dev database fresh: drop database `klenz`, restart the API. On the live site the admin is the source of truth: changes to `seed.py` never reach it; text defaults only via `PREVIOUS_DEFAULTS`.
- Git Bash heredocs mangle backslashes and long scripts with quotes; edit files with the editor tool instead.
- Open question for the client: the visiting card says Pollachi **642001**, the catalogue **642002** (setting `address`).
- After changes: backend `pytest`; frontend `npm run build` + `npm run lint`; check phone/tablet/desktop widths in the browser's device toolbar.
